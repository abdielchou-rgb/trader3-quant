## 一、从 2hao 写作管线学到了什么（深读结论）

### 1.1 2hao 写作管线的完整链路

```
report_generator.generate_report()
  ├─ 1. task_router 选路径（管线/工作台）
  ├─ 2. REPORT_SKILLS 按类型加载 skill（含 author_pose / roundtable_review）
  ├─ 3. REPORT_ENGINES 注入框架引擎（计算摘要）
  ├─ 4. context_compiler 组装上下文（含作者姿态硬约束 + 框架适配清单）
  ├─ 5. 写作（Claude 用 ctx 生成）
  ├─ 6. verify_report_text 门禁（工作过程/元评论扫描 + LLM rubric）
  ├─ 7. roundtable_review 圆桌评审（4角色独立批判）
  └─ 8. export_report → VisualGate → IronGate → 通过才出门
```

### 1.2 核心纪律（3hao 必须继承）

| 纪律 | 2hao 如何落地 | 3hao 对应 |
|------|--------------|------------|
| **作者姿态** | context_compiler 注入硬约束：只陈述事实/数据/结论，禁止元评论/工作过程/版本迭代语言 | 买卖点提醒、简报、方案全部遵守 |
| **门禁阻断** | verify_report 扫描工作过程词（补采/差距采/见3.2）+ 元评论词（建议验证/待核实/值得关注） | 每次输出前跑关键词扫描 |
| **数字可复算** | IronGate 数测：市场规模口径统一/指标单一事实源/来源实体化 | 提醒里的目标价/止损价必须标注计算来源 |
| **独立评审** | roundtable 4角色独立批判，防"自己写自己改"天花板 | 高确信提醒发前跑一轮"反向批判"（devil's advocate） |
| **结论唯一** | Bold Call 单一事实源、explicit_conclusion 硬要求 | 每条提醒必须给出明确的"买/卖/观望"主结论 |
| **框架适配防错配** | industry_hint 注入适用框架，宏观 DDM 不注入内需行业 | 行业判断用对应行业框架，不用错框架 |

### 1.3 2hao 的作者姿态硬约束原文（最关键）

```
你是报告作者，不是写作助手。正文必须：
· 只陈述事实、数据、分析、结论
· 不教读者如何验证/如何尽调
· 不解释本报告如何得出
· 不自指见某节/本报告
· 不出现可考虑/需评估/建议对等助手式措辞
```

**这是 3hao v2.0 写作的第一铁律。** 买卖点提醒不是"建议你考虑买入"，而是"今日触发买入条件，理由如下"。

## 二、3hao v2.0 三种产物的写作规范

### 2.1 买卖点提醒（急提醒 / 立即通知）

**触发**：三因子（催化×预期差×技术确认）同时成立 + 2hao 研究正面 + 3hao 验证通过。

**写作规范**（30秒内读完）：

```markdown
【3号交易员·买入提醒】{股票名}({代码}) 今日触发买入

结论：买入区间 {价格区间}
依据：
· 预期差：当前价 {X} 低于 DCF 中枢 {Y}（低估 {Z}%），{催化事件}将驱动预期修正
· 技术确认：价格上穿 {关键位}，成交放量 {W}%
· 状态迁移：{状态机} 观察→买入区间

风险：{最大风险1句}；若跌破 {止损价} 则取消买入逻辑

来源：trader3 三因子触发（催化强度/估值分位/技术确认）| 2hao研究结论：正面
验证：IronGate 通过 | 非投资建议，候选信号
```

**禁止**：不写"建议关注"“值得观察""可以看看"；写明确结论+区间+依据+风险。

### 2.2 每日分析简报（晨间/盘后）

**结构**（复用 2hao 报告骨架但压缩为简报）：

```markdown
# 3号交易员 · 每日简报 {日期}

## 宏观温度（高频景气快照）
· 今日高频指标：粗钢{↑2%}/30城成交{↓5%}/乘联会销量{↑1%} → 制造业库存周期偏暖

## 行业景气扫描（Top3 变化）
| 行业 | 景气变化 | 驱动 | 对应跟踪股 |
|------|---------|------|-----------|
| 半导体设备 | 上修 | 大基金三期催化 | {股票A} |

## 自选股跟踪（状态变化才列）
{股票B}：观察→预警（财报应收增速>收入增速，触发财务红旗）
{股票C}：持有中，接近目标价 {X}，距止损 {Y}%

## 今日催化日历
· {时间} {公司} 股东大会 / {公告}
```

**禁止**：每天列"无操作建议"的废话；只有状态变化/景气变化/催化才写，否则只写温度行。

### 2.3 定期交易方案（周/月）

**结构**（对接 optimize_portfolio 输出 + 2hao 决策备忘录骨架）：

```markdown
# 3号交易员 · {周/月}交易方案 {期间}

## 组合现状
· 持仓 {N} 只 / 仓位 {P}% / 本月收益 {R}% vs 基准 {B}%

## 调仓建议（仅在有动作时给）
| 动作 | 标的 | 理由 | 权重变化 |
|------|------|------|---------|
| 加仓 | {股票} | 预期差扩大+景气上修 | 3%→5% |
| 减仓 | {股票} | 逻辑破坏（{事件}） | 5%→2% |

## 风险监控
· 市场状态：{regime}，止损线 {X}，仓位红线 {Y}

## 来源
· 组合权重：trader3.optimize_portfolio | 预期差：trader3.valuation_anchor
· 行业判断：2hao 行业框架 | 全部为候选信号，非投资建议
```

**禁止**：方案里出现"建议可考虑加仓"；直接给"加仓/减仓/持有"+理由+权重。

## 三、与 2hao 管线的对接接口（技术细节）

### 3.1 三种产物各自的"写完之后"必须跑

| 产物 | 复制 2hao 的哪些检查 |
|------|---------------------|
| 买卖点提醒 | 作者姿态自查 ≤3 条 + 数字来自 valuation_anchor/三因子记录 + 反向批判1轮 |
| 每日简报 | 扫描工作过程词/元评论词（复用 template_blacklist 思路）+ 数字带来源标注 |
| 定期交易方案 | 复用 report_generator.verify_report_text() 的 verify 扫 + LLM rubric 打分 |

### 3.2 可复用的 2hao 模块（直接调用）

```python
# 写作后门禁（3hao 三种产物都跑）
from core.template_blacklist import scan_work_process, scan_metacomment
issues = scan_work_process(text) + scan_metacomment(text)

# LLM rubric 软评分
from core.compute.llm_rubric import llm_score_report
score = llm_score_report(text, use_llm=False)

# 行业框架适配（简报判断行业时防错配）
from core.context_compiler import framework_fit_prompt
hint = framework_fit_prompt("半导体设备")  # 注入对应行业框架
```

### 3.3 反向批判（自写时替代圆桌）

高确信买卖提醒发前，强制跑一轮：

```
角色切换：你不再是写作助手，是审计师。
查：① 结论是否夸大（预期差数据是否来自真实估值计算）
② 是否漏了反向因素（行业下行/财务红旗）
③ 止损逻辑是否可执行（价格是否真实可触发）
任一不通过 → 降级为"简报关注"，不触发急提醒
```

## 四、一句话总结

> **3hao v2.0 的写作 = 2hao 的作者姿态 + 3hao 的数字验证。买卖点提醒说人话、给结论、带依据、标风险；简报只报变化不灌水；方案直接给动作和权重。所有产物过「作者姿态 + 数字来源 + 反向批判」三道关才出口。**
